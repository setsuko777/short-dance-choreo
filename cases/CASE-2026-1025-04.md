## 5. 关键发现

### ① 纯色背景彻底解决了「背景衰减」问题

CASE-12 的背景是深蓝黑舞台 + 白烟雾 + 金蓝飞溅（动态素材），实测背景带 std
从 24.2 单调衰减到 10.4——动态元素在长时序上守不住。

本例换成**纯色背景**后：

| 时间点 | 背景 RGB | std |
|---|---|---|
| 0.000s | 242/195/149 | 38.1 |
| 6.889s | 240/193/147 | 40.6 |
| 15.042s | 241/195/149 | 38.0 |

**std 全程稳定在 38–40，无衰减** ✅

**结论：要求背景绝对静止时，素材必须是纯色背景；动态素材（烟雾/粒子）在 15s 尺度上做不到。**
这条验证了我当初在 CASE-12 §7.5 提的推测——现在有了对照数据。

### ② 「生成侧无音轨」是我取错文件导致的误判（重要修正）

本例发现 ComfyUI 输出的是**两个文件**：

| 文件 | 内容 |
|---|---|
| `oneshot_00001.mp4` | 视频，**无音轨** |
| `oneshot_00001-audio.mp4` | 视频 + **音轨** |

之前的 runner 按前缀匹配，先命中无后缀的主文件，所以我一直判定「生成侧无音轨、
需后期配乐」，还写进了 CASE-12 §7 已知限制、SKILL.md 与 CHANGELOG。

**真实情况**：取 `-audio.mp4` 就有音轨，且音轨内容与原曲窗的
能量包络相关系数 **0.997** —— 就是原曲，`audio_mode=lock_source` 生效。

已修 `run_oneshot.py`：优先取 `-audio.mp4`，取不到才回退并打印提示。
CASE-12 成片据此换成原生音轨版（不再后期混入）。

### ③ 传本地路径会 400（另一处工具缺陷，已修）

`--audio ../cases/assets/qw21_oneshot.wav` 直接提交报 HTTP 400：

```
audio - Invalid audio file: ../cases/assets/qw21_oneshot.wav
```

ComfyUI 的 LoadImage / LoadAudio **只认 input 目录下的文件名**，不接受本地路径。
之前能跑通是因为默认音频文件早就在那个目录里。

已修：新增 `ensure_comfy_file()`，传本地路径时自动同步到 ComfyUI input 再转文件名。
同时给 `post()` 加了 400 响应体读取——原先只能看到裸 traceback，看不到真正原因。
