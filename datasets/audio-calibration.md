# 音频实测校准记录（M3 + M4 勘误）

> 版本：v1.1（2026-10-24，M4 端到端实测后发勘误）· 数据来源：`scripts/beat_tracker.py` 全量实测 · 测试曲目：剪映云端音乐库缓存 3 首（慢/中/快）
> 本文档是 R1 角色的校准档案：记录工具链在真实曲目上的行为、边界与已知限制。**所有数字可复现**（重跑 `scripts/tests/test_beat_tracker.py` + CLI）。

## ⚠️ M4 勘误（2026-10-24）：段落检测误报，M3 结论作废

M3 版本记录的三曲段落结构（Ukulele drop@47.16s / Lowride drop@163.63s / 快闪兜底 drop@27.81s）**全部误报**。M4 为选窗口而核对每秒 RMS 地面真值时发现：

| 曲目 | M3 误报 | 地面真值（每秒 RMS） | M4 修正后 |
|---|---|---|---|
| Ukulele | drop@47.16s | 0–20s ≈0.05–0.16（低）→ **20s 起 ≈0.21–0.26（高）** | drop@**19.69s**（intro 0–9.5 → verse 9.5–19.7 → drop 19.7–102 → verse 102–120 → chorus 120–146.5） |
| Lowride | drop@163.63s | 全程 0.05–0.11 无显著跃变（前 20s 略轻 0.05–0.07） | drop@**18.99s**（groove 进入点；本曲**无结构性 drop**，该值为最接近的跃变点） |
| 快闪 | 兜底 drop@27.81s | 0–8s 稀疏鼓点（0.036/0.153 交替）→ **9s 起 0.17–0.30（满编）** → 26s 衰减 | drop@**8.52s**（intro 0–8.5 → drop 8.5–30.5；不再需要兜底） |

**根因**：M3 的百分位 regime 量化（35/65 百分位）在「高能平台占全曲多数」的曲目上两个阈值都落进平台内部，按平台自身起伏乱切。**修复**：改为相对 90 分位稳健峰值的固定比例阈值（高能 >72% 峰值 / 低能 <40% 峰值）——三曲修正后的结构与 RMS 地面真值一致，M0 合成轨准出不受影响（回归 PASS）。

**教训（记入 R1 纪律）**：段落标签的「合理性」不能靠标签字面判断，必须与每秒 RMS 曲线核对；启发式输出需有地面真值抽检机制。

**不受影响的部分**（M3 结论仍有效）：BPM 估计、DP 自洽、拍召回、downbeat 间距稳定性、群延迟补偿——这些指标与段落检测独立，M4 复测全部通过。

## 二、M3 实测发现的问题与修复

### 发现 1：段落碎裂（已修）

**现象**：Lowride 初版输出 5 个连续 verse 段（62→112→124→135→163s），把 101s 的主体切成了碎片。

**根因**：`detect_sections` 的能量 regime 量化按 level（0/1/2）合并短段，但 level 0 与 level 1 都映射为 `verse` 标签，相邻同标签段没有二次合并——能量在 verse 内的轻微起伏被放大成段落边界。

**修复**：标签映射后增加「相邻同标签合并」（level 取 max）。修复后 Lowride = intro/verse/drop/chorus 四段，结构合理。回归测试确认另两曲不受影响。`beat_tracker.py` 已更新，M0 合成轨准出仍 PASS。

**残留限制**：段落标签仍是启发式。细粒度 verse/chorus 划分（如双 verse 结构）允许人工修正，修正记录进 changelog。

### 发现 2：快板曲「每镜 1 bar」网格违宪（已修，本 milestone 最重要）

**现象**：宪法 6 原写「每镜时长 = 相邻 downbeat 之差（2–3.5s）」。实测枚举发现该规则只在部分 BPM 可行：

- **bar < 2.0s（BPM > 120）**：1 bar 低于单镜下限，2 bar（>3.5s 当 BPM < 137）超上限 → 120–137 BPM 区间无合法 bar 网格。128 BPM 15s 版在原规则下**无解**
- **bar > 2.7s（BPM < 89）**：15s 铺不满整数 bar（5×2.727=13.6s，余 1.4s < 2.0s 下限）→ 88–94 BPM 也无解
- 6s 精简版 3 镜只在 **BPM = 120.0±0.1** 成立（3×2.0s=6.0s 整网格；M4 实测 120.25 差 3.3ms 即违宪——「≈120」的表述已修正）；104 BPM 时 3 bar=5.77s 余 0.23s、拍吸附 3 镜需 ≥12 拍=6.9s → 只能 2 镜

**修复**：吸附单位三级优先 + 网格枚举器 `scripts/shot_grid.py`（单测 `tests/test_shot_grid.py` 全过）：

1. **bar 吸附**（首选，切点落小节线）：每镜 1 bar（慢板可 2 bar），末镜截短 ≥2.0s
2. **拍吸附**（快板兜底）：每镜 4–8 拍整数拍，切点落拍；产出标注「拍吸附模式」
3. **2-bar 吸附**（极快板）：BPM ≥148 时 2 bar ≤3.5s，回到整数 bar 单位

排序键：bar 模式强优先（舞蹈剪辑惯例切点落小节线）→ 镜数接近 6 → 时长方差小。无解时脚本 exit 2 如实报错，禁止手捏违宪切点。

**常用 BPM 网格速查**（枚举生成，详见 `references/beat-analysis.md`）：88–92 拍 5 镜｜95–104 bar 6 镜｜108 拍 6 镜｜112–120 bar 7 镜｜124–140 拍 6 镜｜148–160 bar 5 镜｜174–180 拍 6 镜。

**回归保护**：M1 两个样例的网格（15s@96=6×2.5s、6s@120=3×2.0s）已写成单测断言，后续改排序逻辑会立刻暴露。

### 发现 3：检测器群延迟的系统性补偿（复核确认）

M0 已在合成 click 轨上校准 -28ms 群延迟并做常数补偿。本次 3 曲 downbeat 间距偏差 ≤34ms（且中位数 ≤17.8ms），确认补偿在真实音乐上同样成立。**注意**：换解码参数（采样率/帧长）需重新校准此常数。

## 三、已知限制（如实记录，写入 R1 规范）

1. **段落标签是启发式的**：intro/verse/chorus 边界大致可信；双 verse、bridge 等结构可能被并段。允许人工修正；**标签合理性必须与每秒 RMS 曲线核对**（M3 曾因只看标签字面而全曲误报，见文首勘误）
2. **速度歧义不私自裁定**：Lowride 的 104.25 vs 156.4（×1.5）由 `bpm_alternatives` 暴露 top-3，最终人工抽检裁定。本机 3 曲的 top-3 分数差 <0.003，歧义风险低但机制必须在
3. ~~**兜底 drop 的可信度**：快闪鼓点无低→高能量跃变，drop 走 onset 密度兜底（27.81s）~~ —— **M4 修正后作废**：修复后的检测器在快闪上直接测得真入口 8.52s（intro→drop 跃变），不再触发兜底。兜底机制保留（防全程无跃变曲），但本机 3 曲均不触发
4. **首拍不起算原点**：Ukulele 首拍在 643ms（弱起 intro），之前无拍。跨曲比较时注意「拍计数」以首拍为原点，不用 0
5. **BPM 假设路径**：纯文字输入（无音频）时按感觉词区间假设（见 `beat-analysis.md` 感觉词表），产出标注「节拍为假设值」；**假设节拍在 15s 尺度不可用**（0.5 BPM 误差累积 160ms 超容差，见 cases/README.md 基线对比）
6. **librosa 为可选增强**：1.0.0 已实装且 py3.13.14 import 正常，但默认路线（numpy 零依赖）不依赖它；librosa 不可用不 block
7. **ffmpeg seek 在剪映 m4a 上约 20s 偏差**（M4 实测）：`-ss` 输入/输出两种模式的落点都与全解码时间线不一致。**窗口裁切必须用 `scripts/trim_window.py`**（全解码→样本切片→编码）
8. **短窗（<30s）downbeat 相位不稳定**：窗内相位与全曲分析可差约 3 拍（CASE-03 实证：窗内首 downbeat 1.80s vs 全曲相位 0）→ 窗内切点优先拍吸附；段落检测在短窗用自适应参数（平滑 2s / 最短段 3s）

## 四、复现方式

```bash
# 全量测试（合成轨 + 3 真实曲目 + 准出判定）
python scripts/tests/test_beat_tracker.py
# 单曲分析（JSON 落盘）
python scripts/beat_tracker.py <audio> -o out.json
# 样本级窗口裁切 + 窗内分析（M4 起的标准入口）
python scripts/trim_window.py <audio> --ss 12.6 -t 15 -o window.wav --json window.json
# 镜头网格枚举
python scripts/shot_grid.py 15 <bpm>
```
