## 单次直出的显存预算（v2.0 实证，本地 H3）

「单次时长 ≤ 上限」只是**能力**准入，不等于**能跑起来**。显存随「帧数 × latent 面积」增长，
长时序直出的真实瓶颈是显存，不是时长上限。

### 显存账怎么算（可直接套用）

```
总显存 ≈ 固定开销 + 13.12 MiB × 帧数 × 分辨率(MP)
```

- **13.12 MiB/(MP·帧)**：从 OOM 报错的 `Requested 5.45 GiB` 反推（362 帧 @ 816×1440）
- **固定开销 ≈ 8.1~9.5 GiB**：权重 + 激活 + VAE（8.1 为静态态，9.5 含采样峰值）

这是**乘积**关系，所以长视频直出是显存杀手：15s 相比 3s，帧数 ×4.96，再乘分辨率，轻易翻倍。
**走第二遍时更苛刻**：L1（第一遍 latent）与 L2（upscale 后）会同时驻留，
L2 ≈ 2.25 × L1（1.5x upscale），合计 3.25 × L1。

### 16GB 卡（可用 15.89 GiB）实测

| 配置 | 输出 | 显存 | 耗时 | 结果 |
|---|---|---|---|---|
| 逐镜 + 两遍 | 832×1472 | ~12 GiB | 2.5–3 min/镜 | ✅ 常规路径 |
| **直出 + 两遍 · 默认设置** | 832×1472 | 需 15.98 GiB | — | ❌ **OOM** |
| **直出 + 两遍 · 开两个省显存杠杆** | **832×1472** | **15.08 GiB（92%）** | **20m46s** | ✅ **跑通** |
| 直出 + 单遍（跳过 upscale）· 544×960 | 544×960 | ~12.0 GiB | ~3 min | ✅ 快但软 |
| 直出 + 单遍 · 832×1504 | 832×1504 | 15.30 GiB（96%） | 20 min | ✅ 余量仅 4% |

### 保住第二遍（upscale refine）的两个杠杆

第二遍是画质的关键——实测同样 15s 直出，**两遍比单遍锐度 +78%**（见下）。
要让它在 16GB 上不爆，靠这两个：

**① attention 后端换 INT8 量化**（本工作流 `ModelAttentionBackend` 节点）

```
pytorch attention（默认）  →  comfy kitchen attention（INT8，仅 Nvidia/AMD）
```

视频的 attention 是长序列，显存大头就在这里。

**② latent upscaler 权重换 fp16**（`MiniMaxH3LearnedLatentUpscaleT8Advanced` 节点）

```
h3_upscaler_sharpness_2000steps_v0.1_fp32.safetensors（默认，fp32）
→ minimax_h3_latent_upscaler_3d_fp16.safetensors
```

默认那个 upscaler 是 **fp32** 的，白白占一倍权重显存。

**实证（CASE-2026-1025-02，两个杠杆同时开）**：362 帧 @ 816×1440 第二遍采样，
从「需 15.98 GiB → OOM」变为「15.08 GiB 跑通」，省下约 0.9 GiB。
⚠️ **未分别量化**：两个杠杆是组合开启的，各自贡献多少没单独测过（各需 20 分钟）。

### 第二遍值不值：值（实测）

同一条提示词、同一 seed，两版都放大到 1080×1920 后对比拉普拉斯方差：

| 时间点 | 单遍 832×1504 | 两遍 832×1472 | 提升 |
|---|---|---|---|
| 1.0s | 42.6 | 79.6 | +87% |
| 4.0s | 61.6 | 86.7 | +41% |
| 6.889s（drop） | 45.6 | 89.1 | +96% |
| 10.0s | 53.6 | 88.4 | +65% |
| 13.0s | 42.4 | 84.8 | +100% |

**平均 +78%**。即两遍版即使分辨率略低（1472 vs 1504），成片明显更锐。
**结论：能跑两遍就跑两遍**——单遍提高分辨率弥补不了 refine 的锐度损失。

### 通用降级顺序（OOM 时按此顺序）

1. **开两个省显存杠杆**（INT8 attention + fp16 upscaler）—— 不改画质，纯赚
2. **降第一遍分辨率**（`--mp`）：L2 = 2.25×L1，降 L1 收益是 3.25 倍
3. **砍掉第二遍**：把保存节点改接第一遍输出，把省下的显存换成第一遍分辨率
4. **降帧数** / 改回分段（逐镜拼接）—— 走到这步已是放弃直出的信号
5. **环境层**：关掉浏览器硬件加速等占显存程序；ComfyUI `--lowvram` / `--normalvram`
6. **硬件**：≥24GB

**工具开关**（`scripts/run_oneshot.py`）：

```bash
# 目标：保住第二遍（推荐）
python run_oneshot.py --with-upscale --attn "comfy kitchen attention" \
                      --upscaler minimax_h3_latent_upscaler_3d_fp16.safetensors

# 退路：砍第二遍，把显存换成分辨率
python run_oneshot.py --mp 1.2
```

**未量化项**：13.12 MiB/(MP·帧) 与 8.1~9.5 GiB 固定开销来自单卡单工作流的实测点，
两个杠杆的单独贡献也未测。跨卡 / 跨工作流会有偏差，遇到 OOM 按上面顺序降级并补记实测点。
