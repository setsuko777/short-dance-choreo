# 角色素材规范 — 四视图（Character Sheet）

> 归属 R5 提示词工程师 / R4 镜头导演共同使用；处理工具 `scripts/split_char_sheet.py`。
> 实证来源：CASE-2026-1025-01（QW21 四视图，H3 六镜，2026-10-25）。

## 1. 为什么需要四视图

逐镜拼接模式下，一条 15s 成片要覆盖 **5 处身体特写 + 4 种以上镜头角度**。
单张角色图只能支撑「正面起手 + 默认景别」，一旦镜头要切纯侧 / 背身，或景别要落到眼 / 嘴 / 胸 / 大腿 / 小腿，
模型就只能凭提示词脑补——这正是 `drift 漂移` 与 `framing 构图失败` 两类废片的主要来源。

四视图的作用不是「多喂几张图」，而是**给每个镜头一个真实的对应角度来源**：

| 视图 | 支撑的镜头 | 缺它时的后果 |
|---|---|---|
| `front` 全身正面 | 起手 hook、收尾定格、全身卡点 | 起手只能是默认全身，构图不可控 |
| `bust` 半身特写（正面） | 眼 / 嘴 / 面部特写 | 面部特写靠脑补 → 五官漂移、瞳孔色变 |
| `side` 全身纯侧 | 纯侧脸、侧身律动 | 宪法要求的「纯侧角度」无来源，只能删镜 |
| `back` 全身背面 | 背身镜头 | **宪法硬约束**：无背面图禁止排背身镜 |

## 2. 合格标准

**通用（每一格都必须满足）**：

- 同一套服装 / 发型 / 配色 / 光照方向；跨格外观必须一致（否则 identity 槽位自相冲突）
- 背景近似纯色（灰底最佳），各格背景色一致 → 自动切分依赖背景检测
- 单格短边 ≥512px；全身格高度 ≥1024px（要经得起裁到 9:16 特写）
- 角色不与相邻格粘连：**格之间必须有纯背景竖缝**（宽 ≥ 图宽 1.2%，自动检测的默认值）

**各格专项**：

- `front`：全身入画，脚底到头顶完整，无裁切；水平居中
- `bust`：头顶到胸/腰，头部占比 ≥ 格高的 1/3；眼、嘴可见（长刘海遮挡嘴是常见失败项，见 §7）
- `side`：纯正侧 90°（不是四分之三侧）；轮廓清晰
- `back`：完整背面，头发/背部服装细节可见

## 3. 采集方式（三选一）

1. **直接用现成设定图**：官方设定集 / 已出好的 turnaround 图，横向排列为佳
2. **绘图模型生成**：提示词要点 `character sheet, turnaround, front view / side view / back view, same character, same outfit, plain gray background, full body, reference sheet`；**必须逐格校验同一套服装**（模型在 4 格之间跑偏服装是高发问题，跑偏就重roll，不要将就）
3. **手工拼**：把已有的多张单角度图拼在一张画布上，格间留足纯色竖缝

## 4. 处理流程（`scripts/split_char_sheet.py`）

```
--detect  看自动检测结果（背景色 / 分隔缝 / 每格 bbox），不写文件
--split   切格，纵向统一到整体 bbox（保证各格脚底对齐、比例一致）
--anchors 生成 3 张粗锚点：full / upper / lower（contain 模式）
--probe   出纵向条带刻度图，用于视觉定位眼/嘴/胸/大腿/小腿的比例区间
--tune    按探针读数人工定稿某个特写锚点，参数写入 <tag>_anchors.json
--sync    复制到 ComfyUI input/（Hybrid 路线的 LoadImage 只认这个目录）
--replay  换图/调阈值后，按 anchors.json 重生成全部已定稿锚点
--all     = --split --anchors --sync
```

```bash
python split_char_sheet.py --src 角色图.png --map bust,front,side,back --outdir ../cases/assets
# 依次跑 detect → split → anchors → probe → tune → sync
```

**`--map` 必须按图从左到右给角度名**，名字即后续引用名（front / bust / side / back 仅为约定，可自定义）。
不给 `--map` 时退化为 `view1..viewN`，此时需要人工确认每格角度。

**自动化边界（诚实说明）**：脚本能可靠做「切格 + 全身/上下半身粗锚点 + 探针刻度」；
**眼 / 嘴 / 胸 / 大腿 / 小腿的精确比例因角色而异，不能自动推导**，必须走 `--probe` 出刻度图 → 视觉读数 → `--tune` 定稿。
这是有意为之：自动猜比例会静默产出裁歪的锚点。

## 5. 槽位分配（一个参考一个职责）

多图不等于多喂。四视图进槽位的原则（继承 `prompt-templates.md` 槽位分配表）：

| 槽位 | 喂什么 | 禁止 |
|---|---|---|
| identity | `front` + `bust`（同主体不同景别，职责一致） | 同时喂 front + back（模型会取中间角度） |
| first_frame（构图锚点） | **只喂 1 张**——由 `split_char_sheet.py --tune` 产出的该镜锚点图 | 喂原格图（景别不对）、喂多张（职责冲突） |
| 背面镜 | `back` | 用 front 靠提示词说「背身」（失败率极高，宪法禁止） |
| 纯侧镜 | `side` | 同上 |

## 6. 构图锚点纪律（DG-019，实证）

`--anchors` / `--tune` 默认 `contain` 模式（完整装下 + 四周留背景边），**不默认 `cover`**。

实证结论（CASE-2026-1025-01 六镜）：

- 顶格特写锚点（主体占画面 >0.85）会触发 **DG-019**：H3 在约 1.5s 处把景别**硬跳**回默认全身；
  极端档位（胸腰 ECU，无头）不只是跳变，而是**角色本体解体**（头部、项圈、垂饰全部消失）——落点若恰在 drop 命中帧，
  整条成片报废。
- 修法：**锚点必须保留上下文**——取景含「完整头部 + 肩」或「裙摆→脚」这类自然边界，
  而不是把目标部位顶满画面。脚本 `--mode cover` 因此标记为高风险档，用时须在案例文档注明。
- 曾尝试用「主体占画面比例」量化锚点紧度并推出「越紧越跳」的单调结论——**该指标已证伪**
  （比例值会在 0.455↔0.998 之间跳，角点背景采样在主体贴边时失效）。当前度量手段是
  **帧间 MAD + 视觉确认双轨**，见 `cases/CASE-2026-1025-01.md` §6B.2。

## 7. 已知限制与坑（实证）

1. **嘴部可能不可见**：长刘海角色在 `bust` 格里嘴常被遮住。此时嘴部镜的锚点只能给到「下半脸近景」，
   嘴的可见性交由提示词显式声明 + QA 第 1 查逐帧抽检；**并在案例文档中如实记录该限制**。
   （CASE-2026-1025-01 最终 H3 自行生成了清晰可见的唇，故限制未发作，但源图层面确实无唇色命中。）
2. **细结构会被 bbox 过滤**：呆毛 / 发梢 / 手指这类只有几个像素宽的结构，在行列判定阈值下会被滤掉，
   表现为「头顶被裁一点点」。脚本默认值 `THIN=0.001`（一行/列需 > 宽度×0.001 个非背景像素才计入）已按此修正；
   若仍出现细结构丢失，调小 `--tol` 而不是调大 `THIN`。
3. **背景非纯色时自动检测会失败**：渐变 / 带纹理的背景会让分隔缝检测不到或误判。
   先给 `--bg R,G,B` 手动指定背景色，再跑 `--detect` 复核；仍不行则改用手工坐标（退化为 `split_qw21.py` 那种硬编码方式）。
4. **格数 ≠ 4 也能用**：脚本按检测到的缝数切 N 格，2 格 / 3 格 / 5 格同样支持，只是可支撑的镜头角度相应减少（见 §8）。

## 8. 退化路径（视图不全时）

| 手上有 | 可用角度 | 编排调整 |
|---|---|---|
| 4 格（front/bust/side/back） | 全部 | 无限制 |
| 3 格（缺 back） | 正面 / 纯侧 / 面部特写 | **删所有背身镜**；宪法硬约束，不得用提示词硬凑 |
| 3 格（缺 side） | 正面 / 背面 / 面部特写 | 纯侧镜降为四分之三侧；角度序列需重新排避免连续重复 |
| 2 格（front + bust） | 正面 + 面部特写 | 镜头语言退化为「正面景别变化」，俯仰/环绕禁用；典型 4 镜 |
| **1 张图** | 正面单一角度 | 走 first-frame 槽位；镜头降为 3–4 个；建议走**直出模式**（见 SKILL.md Phase 2.6），
  多镜头拼接在低信息量参考下性价比很差 |

每一次退化都要在案例文档里写明「因缺少 X 视图，删/降了 Y 镜头」——这是 R7 回流统计的输入。
